# Research forensic audit — before implementation

Recorded September 9, 2026 against `db01ee0`, before any source-code changes in this phase. The checkout was clean. Eight frozen model/journal/research files were hashed without unpickling models or running the reserved evaluator. Three independent read-only reviews covered quantitative/data integrity, simulation/accounting, and lineage/security; the coordinating review traced storage, features, strategy generation, benchmark execution, historical experiment ledgers, MCP/configuration and operational health.

The previous implementation materially strengthened order safety. It does not yet provide sufficient infrastructure or data evidence to establish persistent alpha. These priorities refer to what would invalidate or exaggerate a new research claim; existing synthetic examples are already labeled as engineering tests.

| Priority | Finding from actual code | Required response |
|---|---|---|
| P0 | `atlas/strategies.py:validate_bars` retains a close timestamp and values but no information-availability, ingestion, venue/session or revision identity. `storage.py` records dataset collection time, not a point-in-time revision stream. A late or revised historical observation can look contemporaneously available. | Introduce an explicit canonical contract, quality report and point-in-time feature snapshots; never infer availability from candle close alone. |
| P0 | `atlas/config.py`, `service.analyze` and MCP benchmark/ranking have no sealed data-access role or durable holdout claim. A dataset labeled holdout remains inspectable. | Exclude sealed data from development tools; bind partitions/content to an operational seal with one durable evaluation claim. No retrospective claim that already viewed data is untouched. |
| P1 | `atlas/analytics.py:_simulate` fills unlimited fractional all-cash orders at the next observed open and forcibly liquidates at the final close. It lacks latency, spread/depth, partial fills, minimum lots and realistic cancellation. | Use an event-driven replay with explicit order eligibility, fill rules, liquidity budgets and execution-model versions. Leave positions marked or use a separately declared terminal execution event. |
| P1 | `atlas/brokers/paper.py` fills marketable limits completely against the current fixture. Repeated orders can reuse the same displayed depth; resting orders never progress. Fee assumptions are not pinned in persistent metadata and can change reservation math after reopening. | Add a separate persistent replay/paper accounting core with shared event liquidity and pinned execution assumptions; refuse incompatible state rather than silently migrate. |
| P1 | `service.performance` attributes pooled average-cost sell P&L to the exit strategy, even when another strategy funded the position. | Distinguish order attribution from position/lot strategy accounting; do not present exit-attributed results as per-strategy alpha. |
| P1 | MCP benchmark results are returned without a durable attempt record or immutable manifest. `experiments.py` only records selected legacy paths, permits missing hashes and has no concurrent durable attempt claim. | Reserve every variant before computation; preserve failed/aborted attempts and bind source/data/feature/strategy/execution/split/seed/result lineage. |
| P1 | `StrategyRegistry` accepts descriptors without implementation identity; code returning the same immediate result can retain a signal ID. | Hash complete versioned strategy definitions and implementation/source lineage; refuse ambiguous comparisons. |
| P1 | `EvidenceStore.research` drops actual legacy keys `n_variants`, `ts_utc`, `outcome`, `config_hash`. That hides the recorded selection denominator from AI analysis. | Preserve a safe scalar schema including real attempt counts and report incomplete provenance. |
| P1 | No matched-turnover/random distribution, cost break-even sweep, parameter perturbation, regime attribution, dependent bootstrap or immutable scorecard exists. Fixed window boundaries are context ranges, not evidence of fitted ML OOS superiority. | Build a small predeclared research gauntlet with honest evidence classes and explicit unavailable statistics; count every evaluated variant. |
| P2 | Evidence readers bound result count but scan unlimited file bytes and silently skip malformed records; prediction fields can contain nested data/nonfinite values. | Bound input bytes, flag corruption/truncation and enforce scalar finite output. |
| P2 | Risk lacks portfolio drawdown/correlated exposure/turnover and persisted strategy-health vetoes. Enable state is process-local. | Add explicit server-owned portfolio/health controls where verified inputs exist, with unknown inputs blocking configured limits and no automatic reactivation. |
| P2 | Operational health has no research/drift or paper equity/fill history. Existing account P&L dates are journal-update dates. | Persist timestamped replay fills/equity and evidence-bound health; expose scoped observability without fabricating live measurements. |
| P2 | Exchange calendars, corporate actions, universe membership and source revisions are not established by the available simple bars. | Require explicit contracts or refuse incompatible research; identify unsupported markets rather than silently adjust prices. |
| P3 | New MCP scenario arithmetic does not isolate Decimal context. Historical cache keys pin version/parameters but not full implementation bytes. | Reuse fixed financial context; pin complete source hashes for new research without reinterpreting frozen caches. |

The original feature-v1 volume/label-availability and historical holdout-selection findings still matter. The opt-in v2 path prevents the previously reproduced volume-prefix and cross-asset label-filter defects; it does not prove a data provider delivered those observations at the historical decision time. Frozen model bytes, historical ledgers and one-time forward-test criteria will remain unchanged.

Implementation direction: canonical observations → point-in-time features → independent versioned strategies → immutable experiment attempts → event replay and portfolio accounting → cost/baseline/robustness/regime/uncertainty attacks → evidence-classed scorecards → persistent paper/shadow and strategy health. No additional broker, funded execution, persistent application process or deployment is part of this phase.

Dataset recovery is being inventoried read-only. A missing credible real dataset is a blocker to alpha validation, not permission to substitute synthetic results. Synthetic fixtures may validate only software behavior. Detailed inventory and final findings will accompany the implementation report.
