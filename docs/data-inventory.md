## Research conclusion

**Alpha validation is blocked by missing eligible market data.** No strategy
can be called profitable, promising, paper-ready or shadow-ready on the basis
of the generated examples or these two historical practice snapshots. Historical
performance in `FINDINGS.md` and `FORWARD_TEST.md` remains reported history,
not a reproduced result from this audit. Frozen historical feature/evaluator
problems are described in `quantitative-audit.md` and
`research-forensic-audit.md`; their artifacts are not silently upgraded.

A credible first study needs one deliberately chosen instrument/universe,
documented source and license, sufficient continuous history across regimes,
verifiable publication/revision semantics, explicit adjustment and delisting
handling, and a sealed later period. Costs, quoted spread or its acknowledged
proxy, session/calendar data and volume units must match the execution model.
For equities, dividends/splits and historical universe membership need separate
point-in-time evidence. For crypto, venue/pair changes and actual volume units
must be established. No large download or new feed connection is implied.

## New canonical data interface

`atlas.research.market.validate_dataset(payload, now=...)` accepts explicit
schema `1.0` JSON and returns canonical bars, a full `dataset_hash`, an
`observation_hash`, `descriptor`, `evidence_class` and `quality`.
`load_dataset(path, now=...)` reads at most 32 MiB and rejects duplicate JSON
keys and nonfinite JSON constants. At most 100,000 bars and 100 symbols are
accepted. `quality_report` returns a nonthrowing invalid-input report.

Required envelope fields are `schema_version,dataset_id,source,asset_class,
symbols,venue,price_adjustment,universe,availability_basis,revision_policy,volume_unit,currency,bars`.
Source contains `source_id,kind,description`; `kind` is `real`, `synthetic`,
`test` or `unknown`. Additional optional source URL/license/content hash are
provenance declarations. Price adjustment is explicitly `unadjusted`,
`point_in_time_adjusted`, `retrospectively_adjusted` or `unknown`. Universe
contains a selection method and `known`, `unknown` or `mitigated` survivorship
bias status. Availability basis is `observed`, `provider_published`, `assumed`,
`synthetic` or `unknown`; revision policy is `as_observed`, `latest_only`,
`synthetic` or `unknown`.

Volume units are explicitly `shares` for equities or `base_asset` for crypto;
`unknown` remains a quality blocker and cannot supply replay fill capacity.
The envelope unit is propagated into each normalized bar. Quote-currency volume
or trade counts are not silently treated as instrument quantities.
Quote currency is a required uppercase three-letter code, propagated to every
bar. Non-USD data remains explicitly foreign-currency data; the present replay
refuses it because FX conversion/accounting has not been implemented.

Bars contain normalized symbol/asset class/venue, integer UTC `event_time`
(bar close), `interval_seconds`, `information_available_time`,
`ingestion_time`, `timezone='UTC'`, `session`, `session_date`, OHLCV, integer
`revision` and `source_id`. Bid/ask must both be present or both absent.
Revision reason is optional. Prices are exact, bounded, finite decimal strings
after normalization. Original revision zero is required; corrections increment
the revision with a strictly later information timestamp. Revisions are retained,
never silently overwritten. Input publication order is required, not repaired.

Crypto supports aligned UTC 24/7 bars. Equity supports explicit, versioned
America/New_York regular-session calendars containing dated UTC open/close
bounds; other session models are rejected. Calendar schedules are operator
declarations and are not authenticated holiday calendars. No implicit holiday,
corporate-action or missing-bar repair is performed. Gaps and unknowns appear
in quality metadata and limit the experiment's interpretation.

Evidence classes are `SYNTHETIC`, `TEST` and `HISTORICAL_UNVERIFIED`.
Changing a source label to `real` never authenticates it: `alpha_validation_eligible`
remains false until a future explicit provenance-verification mechanism exists.
The full dataset hash binds all normalized metadata. The observation hash
excludes dataset/source aliases, descriptions and archive ingestion metadata;
it binds the actual observation identities, timing, revisions and values.
An aggregate hash alone is not a proof of independence from overlapping datasets.
`observation_keys(dataset)` additionally identifies stable asset-class, symbol
and event-time tuples; revisions, altered prices and metadata/venue aliases
cannot disguise overlapping market events from the holdout access registry.
This deliberately blocks the same instrument/time across venues because venue
identity has not been authenticated. Arbitrary symbol remapping cannot be proved
equivalent without a trusted historical instrument registry; the normalized
symbol contract and that remaining limitation are explicit.

## Causal features and folds

`FeatureRegistry(lookback=20)` declares eight features: one-bar return,
momentum, unannualized return volatility, average true range, moving-average
distance, volume z-score, quoted relative spread and trailing drawdown.
Each declares units, exact inputs, lookback/warmup, asset compatibility,
availability and missing/session/gap policies. Snapshot output includes per-value
availability, revision/source lineage, input hashes and a definitions hash.
Values reset at session-date changes or missing/changed intervals. Missing
quotes or zero reference variance yield unavailable values, not invented zeros.
`as_of_rows` selects only completed observations/revisions whose declared public
availability is at or before the decision. A later archive ingestion time remains
provenance; it does not invent an earlier original acquisition. This mechanism
does not by itself authenticate the claimed publication time.

`timestamp_folds` provides anchored or rolling train/validation/test ranges in
seconds. It purges each sample whose actual label publication has not occurred
before its window ends, inserts explicit embargo intervals, and prevents
overlapping test windows. Samples may provide `label_available_time`; omission
is disclosed as the assumption that label publication equals `label_end_time`.
Sealed suffix targets are excluded before target access. `validate_fold`
independently checks a proposed fold's indices, chronology and label cutoffs.
The fold helper does not fit a model, select a threshold or authorize access to
a holdout. Those actions require the separate immutable research workflow.

`atlas.research.health` supplies descriptive feature drift, with at least 100
reference and 30 current finite observations per feature before standardized
mean shifts or empirical KS distances are reported. It does not report IID
p-values. Invalid schemas, stale data or bad data quality disable the rule;
small samples stay on watch. An external SQLite `HealthStore` retains status
history and a sticky disabled state across restart. Better data does not
implicitly reactivate a disabled strategy. HEALTHY describes these configured
operational checks and is never evidence of alpha or permission to trade.
Historical daily VaR/expected shortfall remain unavailable below 250 supplied
daily portfolio returns and retain explicit empirical/cash-flow assumptions.

## Primary methodological references

Repeated model selection on the same history can create apparent superiority by
chance. White's benchmark-comparison framework motivates retaining the complete
attempt family. The current joint centered block-maximum diagnostic is not a
certified implementation of that published test and cannot correct unrecorded
earlier attempts. [White (2000), *A Reality Check for Data Snooping*](https://doi.org/10.1111/1468-0262.00152).

Resampling dependent observations needs assumptions about their dependence and
stationarity. The current code uses fixed-length circular moving blocks; it
does not implement the random-length stationary bootstrap. Choosing blocks and
calling a resampled loss fraction a future probability would require additional
validation. [Politis and Romano (1994), *The Stationary Bootstrap*](https://www.tandfonline.com/doi/abs/10.1080/01621459.1994.10476870).

Sharpe estimates and annualization depend on the return-generating process;
serial correlation can invalidate simple square-root-of-time scaling. ATLAS's
descriptive annualization therefore needs an explicit time convention and must
not treat irregular publication events or stale marks as independent daily
returns. [Lo (2002), *The Statistics of Sharpe Ratios*](https://traders.berkeley.edu/papers/The-Statistics-of-Sharpe-Ratios.pdf).
